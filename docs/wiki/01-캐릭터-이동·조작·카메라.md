## 항목별 상세

### 0101

**Character Controller** — 물리 없이 벽·경사를 처리하는 이동 컴포넌트

> 요청 예문: "CharacterController로 WASD 이동과 점프를 만들어줘. 경사 45도까지 오르게 해줘."

- 씬: `Assets/00_Scenes/01_Movement/0101_CharacterController.unity`
- 핵심 스크립트: `CharacterControllerMover`
- 빌더: `Assets/01_Scripts/Editor/Scenes/01_Movement/Build0101_CharacterController.cs`
- 구현 방식: 런타임 데모
- 개념: 캡슐 모양 충돌체를 가진 이동 전용 컴포넌트. Rigidbody 물리를 쓰지 않고 Move() 로 직접 밀어 주며, 경사·계단·벽 밀림을 컴포넌트가 알아서 처리한다. 밀리거나 날아가는 물리 반응이 필요 없는 플레이어 조작에 가장 흔히 쓴다.
- 씬에서 보여 주는 것: WASD·점프, slopeLimit 45° 이하 경사만 오름, 계단은 오르고 턱은 막힘
- 확인 포인트: WASD 로 경사를 올라가 보세요. slopeLimit 45° 보다 완만한 경사는 올라가고 더 급한 경사는 막힙니다. 계단은 stepOffset 만큼 자동으로 올라가고, 그보다 높은 턱에서는 멈춥니다.

### 0102

**Rigidbody 이동** — 물리 엔진으로 미는 이동

> 요청 예문: "Rigidbody 기반 이동으로 바꾸고 FixedUpdate에서 velocity로 움직이게 해줘."

- 씬: `Assets/00_Scenes/01_Movement/0102_RigidbodyMovement.unity`
- 핵심 스크립트: `RigidbodyMover`
- 빌더: `Assets/01_Scripts/Editor/Scenes/01_Movement/Build0102_RigidbodyMovement.cs`
- 구현 방식: 런타임 데모
- 개념: Rigidbody 에 속도나 힘을 주어 물리 엔진이 이동을 계산하게 하는 방식. 충돌·관성·중력이 공짜로 따라오지만 입력 반응이 한 프레임 늦고, 반드시 FixedUpdate 에서 다뤄야 떨림이 없다.
- 씬에서 보여 주는 것: FixedUpdate에서 linearVelocity 이동 vs transform 직접 이동 비교
- 확인 포인트: 왼쪽(물리 이동)과 오른쪽(transform 직접 이동) 두 캐릭터를 같이 움직여 벽에 부딪혀 보세요. 물리 쪽은 벽에 막히고 미끄러지는데, transform 쪽은 벽을 파고들거나 떨립니다.

- 핵심 스크립트: `InputActionsPlayer`
- 빌더: `Assets/01_Scripts/Editor/Scenes/01_Movement/Build0103_NewInputSystem.cs`
- 구현 방식: 런타임 데모
- 개념: 키보드·게임패드·터치를 Move, Jump 같은 추상적인 액션으로 묶어 두고, 장치가 바뀌어도 같은 코드로 받는 입력 시스템. 구 Input.GetKey 방식과 달리 키 재설정·멀티 플랫폼·로컬 멀티플레이를 설정만으로 지원한다.
- 씬에서 보여 주는 것: 코드로 만든 InputActionAsset(Move·Jump·Attack, 키보드+게임패드), 이벤트 로그
- 확인 포인트: WASD 와 게임패드 스틱이 같은 Move 액션으로 들어오는지, 오른쪽 이벤트 로그에 performed/canceled 가 찍히는지 보세요. 패드를 연결해 두면 키보드와 번갈아 써도 끊기지 않습니다.

### 0104

**가속/감속 (Acceleration)** — 바로 최고 속도가 아니라 서서히 빨라지고 멈춤

> 요청 예문: "이동에 가속 0.2초, 감속 0.1초를 넣어서 미끄러지는 느낌을 줘."

- 씬: `Assets/00_Scenes/01_Movement/0104_Acceleration.unity`
- 핵심 스크립트: `AccelerationRunner, AccelerationDemo`
- 빌더: `Assets/01_Scripts/Editor/Scenes/01_Movement/Build0104_Acceleration.cs`
- 구현 방식: 런타임 데모
- 개념: 입력이 들어온 순간 최고 속도로 튀지 않게 목표 속도까지 서서히 올리고, 손을 떼면 서서히 멈추는 처리. 가속·감속 시간이 캐릭터의 무게감을 결정해서, 짧으면 경쾌하고 길면 묵직·미끄러운 느낌이 된다.
- 씬에서 보여 주는 것: 가속 0.2초 / 감속 0.1초 vs 즉시 반응, 속도 그래프
- 확인 포인트: A/D 를 짧게 톡 눌러 보세요. 가속 0.2초·감속 0.1초 캐릭터는 부드럽게 출발·정지하고, 즉시 반응 캐릭터는 딱딱하게 움직입니다. 아래 속도 그래프의 기울기 차이로도 보입니다.
